# JSON CLI Output Contract (Issue #1234/#1268)

## Summary

This document describes the JSON output contract for `openclaw hybrid-mem` commands and explains the current limitations and solutions for issues #1234 and #1268.

## JSON Output Contract

Commands that support `--json` or `--format json` flags **must**:

1. **Output valid JSON to stdout** starting from byte 1 (no log prelude)
2. **Write all diagnostic/telemetry logs to stderr** (not stdout)
3. **Exit with code 0** on success (explicit `process.exit(0)` call required)
4. **Exit with non-zero code** on failure

This contract is required for automation, cron harnesses, and JSON parsers (like `jq`).

## Architecture

### Plugin Logger Redirection

When `--json` is detected in `process.argv`, the plugin wraps the OpenClaw API logger to route all output to stderr:

```typescript
// index.ts:412-413
const logApi = wrapApiLoggerStderrForJsonCli(api);
initPluginLogger(logApi.logger, false);
```

This ensures that all **plugin-generated logs** go to stderr, keeping stdout clean for JSON output.

### Explicit Process Exit

All `--json` commands must call `process.exit(0)` explicitly after outputting JSON. This prevents the process from lingering on plugin handles (timers, DB connections) which can cause:

- Non-zero exit codes despite successful execution
- Hanging processes in automation scripts
- Resource leaks

**Example (goals.ts:66-67):**

```typescript
if (opts.json) {
  console.log(JSON.stringify({...}, null, 2));
  // Issue #1234/#1268: Exit explicitly with 0 after JSON output
  process.exit(0);
}
```

## Current Limitations

### OpenClaw Host Logs Cannot Be Suppressed by Plugin

The **OpenClaw CLI host** itself prints plugin loader logs to stdout **before** the plugin code runs:

```text
[plugins] loading openclaw-hybrid-memory from /path/to/plugin/dist/index.js
[plugins] memory-hybrid: using gateway provider "google" for llm.providers ...
[plugins] loaded 1 plugin(s) (1 attempted) in 127.9ms
```

These logs are generated by the OpenClaw runtime **before** calling the plugin's `register()` function. The plugin **cannot** intercept or redirect these logs because:

1. They are printed by the host process before plugin initialization
2. The plugin has no control over the host's stdout/stderr routing
3. The `wrapApiLoggerStderrForJsonCli` only affects the plugin's logger, not the host's

### Impact

When running commands like `openclaw hybrid-mem config --json`, users may see:

```text
[plugins] loading openclaw-hybrid-memory from ...
[plugins] loaded 1 plugin(s) ...
{
  "schemaVersion": 1,
  "contract": "openclaw.hybrid-mem.config-view.summary.v1",
  ...
}
```

This violates the strict JSON contract because stdout contains non-JSON text before the JSON payload.

### Workaround for Users

Until the OpenClaw CLI is fixed to detect `--json` and suppress host logs, users can:

1. **Use stderr for logs**: Pipe stdout to `jq` and ignore stderr:
   ```bash
   openclaw hybrid-mem config --json 2>/dev/null | jq .
   ```

2. **Parse after host logs**: Skip the first few lines that start with `[plugins]`:
   ```bash
   openclaw hybrid-mem config --json | grep -v '^\[plugins\]' | jq .
   ```

3. **Filter JSON start**: Extract only lines that look like JSON:
   ```bash
   openclaw hybrid-mem config --json | sed -n '/^{/,$p' | jq .
   ```

### OpenClaw CLI Fix Required

The proper fix requires changes to the OpenClaw CLI host:

1. Detect `--json` flag in command arguments before plugin loading
2. Suppress or redirect `[plugins]` logs to stderr when `--json` is present
3. Ensure plugin loader respects the JSON output mode

**This is tracked as an OpenClaw core issue** and cannot be fixed in the plugin alone.

- Output JSON to stdout (plugin logs go to stderr)
- Exit with code 0 explicitly

## Testing

Tests verify that commands:
1. Output valid JSON
2. Call `process.exit(0)` after JSON output
3. Don't leak exit codes from async operations

**Example test (goals-config-cli.test.ts:78-98):**

```typescript
it("exits with code 0 after --json output", async () => {
  const exitSpy = vi.spyOn(process, "exit").mockImplementation((() => {
    throw new Error("process.exit called");
  }) as any);

  try {
    await program.parseAsync(["goals", "config", "--json"], { from: "user" });
    expect.fail("Should have called process.exit(0)");
  } catch (err: any) {
    expect(exitSpy).toHaveBeenCalledWith(0);
  }
});
```
