# JSON CLI Output Contract (Issue #1234/#1268)

## Summary

This document describes the JSON output contract for `openclaw hybrid-mem` commands and explains the current limitations and solutions for issues #1234 and #1268.

## JSON Output Contract

Commands that support `--json` or `--format json` flags **must**:

1. **Output valid JSON to stdout** starting from byte 1 (no log prelude)
2. **Write all diagnostic/telemetry logs to stderr** (not stdout)
3. **Exit with code 0** on success
4. **Exit with non-zero code** on failure

This contract is required for automation, cron harnesses, and JSON parsers (like `jq`).

## Architecture

### Plugin Logger Redirection

When `--json` is detected in `process.argv`, the plugin wraps the OpenClaw API logger to route all output to stderr:

```typescript
// index.ts:412-413
const logApi = wrapApiLoggerStderrForJsonCli(api);
initPluginLogger(logApi.logger, false);
```

This ensures that all **plugin-generated logs** go to stderr, keeping stdout clean for JSON output.

### Direct stdout JSON Writes

JSON payloads now use `process.stdout.write(...)` (not `console.log(...)`) for machine-readable output paths. This prevents host-level console routing from moving payload JSON onto stderr.

## Host-runtime Notes

### OpenClaw Host Logs

The **OpenClaw CLI host** may print plugin-loader diagnostics very early in process startup:

```text
[plugins] loading openclaw-hybrid-memory from /path/to/plugin/dist/index.js
[plugins] memory-hybrid: using gateway provider "google" for llm.providers ...
[plugins] loaded 1 plugin(s) (1 attempted) in 127.9ms
```

These logs are generated by the OpenClaw runtime around plugin loading. Hybrid-memory keeps its own diagnostics on stderr in JSON mode, and keeps JSON payloads on stdout.
Host logs are still outside plugin control because:

1. They are printed by the host process before plugin initialization
2. The plugin has no control over the host's stdout/stderr routing
3. The `wrapApiLoggerStderrForJsonCli` only affects the plugin's logger, not the host's

### Contract in practice

- stdout: exactly one JSON document (or NDJSON lines for `--jsonl`)
- stderr: diagnostics and bootstrap/plugin logs only

## Commands Fixed in #1234/#1268

The following commands now correctly:
- Output JSON to stdout (plugin logs go to stderr)
- Exit with code 0 on success

### Goals Commands

- `goals config --json` ✅
- `goals list --json` ✅
- `goals status --json` ✅
- `goals audit` (always JSON) ✅
- `goals audit --jsonl` ✅

### Config Commands

- `config --json` ✅ (plugin logs to stderr)
- `config --format json` ✅
- `features` ✅ (always JSON)

### Other Commands

See `grep -r "\.option.*--json" cli/` for the full list. Most use the `withExit` wrapper which handles explicit exit.

## Testing

Tests verify that commands:
1. Output valid JSON
2. Keep diagnostics out of stdout
3. Don't leak exit codes from async operations

**Example test (`tests/json-cli-stdout-clean.test.ts`):**

```typescript
it("keeps goals list --json payload on stdout while plugin/bootstrap diagnostics go to stderr", async () => {
  // run wrapped logger in JSON mode, then run goals list --json and assert:
  // - stdout parses as JSON
  // - stderr receives diagnostics only
});
```
